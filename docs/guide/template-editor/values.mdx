# Values, formulas, and conditions

:::tip[In short]
Every field keeps its value under a key. Fields with the same key share one value — across pages too. Formulas compute numbers and texts from those keys, and conditions show elements only while a value matches or a formula holds.
:::

## Where a value is kept \{#value-source}

**Stores value in** chooses where a field's value lives:

- **Custom value (this template)** — the field keeps its own value in the document;
- a value the game already keeps for the document — **Traits**, **Resources**, **Character details**. The field then shows and changes that value, so the dice, other pages, and the rest of the sheet see the same number. Its type follows the game's value.

A page names its document through one field: set a text field to **Character details → Name**. Without such a field the document list shows only the type, and dice rolls carry no name; the editor reminds you under the page while none is set. A text field that is merely called "Name" keeps its own custom value and names nothing.

Changing where the value lives keeps the field's place and look: its width in columns, when it shows, its label settings, and its help text. Settings the new kind of value cannot have are set aside and named for screen readers; switch back before closing the editor and they return.

## Shared value key \{#shared-value-key}

Each custom value is stored under a key — by default, the field's own identifier. **Shared value key** sets that key yourself, in lowercase letters, digits, and dashes (`reputation`, `ship-name`).

Fields with the same key share one value:

- on **one page**, two fields with the key `reputation` show the same number, and changing one changes the other;
- on **different pages** of the same document, a field keeps its value when the reader switches pages: a brief card and a full sheet can show the same `reputation`;
- a key that matches a game value (for example `strength`) links the field to that value.

Removing a field never deletes its value: bring the field back with the same key and the value is still there. Tables and lists have their own shared key for their rows.

## Formulas \{#formulas}

A **Derived value** shows a number or a text computed from other values. Formulas use value keys, numbers, texts in double quotes, `+ - * /`, and parentheses:

```text
passion + self-control
max(0, reputation - 2)
willpower.max
```

For values with a current and a maximum, `.current` and `.max` pick one. Text fields and choices read as text, toggles as 1 or 0.

| Write                          | What it does                                                                                                                                    |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `min(a, b, …)`, `max(a, b, …)` | The smallest or the largest value.                                                                                                              |
| `ceil(x)`, `floor(x)`          | Rounds up or down: `ceil(potency / 2)`.                                                                                                         |
| `round(x)`, `abs(x)`           | Rounds to the nearest whole number; drops the minus sign.                                                                                       |
| `< <= > >= = !=`               | Compares two values: 1 when true, 0 when false. Texts compare with `=` and `!=`. One comparison per part.                                       |
| `and(…)`, `or(…)`, `not(x)`    | Joins conditions: a value holds when it is not 0 and not empty.                                                                                 |
| `if(condition, then, else)`    | One of two results: `if(potency >= 3, "None", "Half")`. Only the chosen result is computed.                                                     |
| `"text" & value`               | Joins texts and numbers: `"BP " & potency`.                                                                                                     |
| `rating(list, "Name")`         | The rating of the list entry with that name, 0 without one. A list following a catalog finds the entry by any of its names, in either language. |
| `row.column`                   | Inside a row button: that row's value in the column (see [Buttons](./elements.mdx#buttons)).                                                    | The editor suggests the keys it knows. A formula that does not parse, refers to a value that does not exist, or depends on itself is listed as an issue; on the page, a failing formula says why instead of showing a wrong number. |

## Limits from values \{#limits-from-values}

A rating or a number can take its maximum from a value or a formula: **Maximum from value or formula** with `willpower.max` keeps a rating at or below the current maximum. Built-in parts of a shipped page take a maximum the same way, and built-in resources a minimum too (**Minimum from value or formula**). When the limit drops, the page shows the value clamped but keeps what was stored; raise the limit and the old value is back.

## Display conditions \{#display-conditions}

**Show only when a condition holds** hides an element until its **Condition** is met:

- **A value matches**: **Value key** names the value, **Comparison** picks equals or not equals, **Value** is what to compare with (`true`, `false`, a number, or text);
- **A formula holds**: the element shows while the [formula](#formulas) gives a number other than 0 or a text that is not empty — for example `rating(disciplines, "Blood Sorcery") > 0`. A formula that cannot be computed hides the element and is listed as an issue.

The editor always shows conditional elements, hatched, and says whether the condition is met on the sample data. Hiding never deletes the element's values.

## Catalogs \{#catalogs}

A **Choice** field can take its options from one of the game's catalogs — weapons, merits, species. Choosing an entry can fill other fields of the page with the entry's details (damage, cost, description): pick which detail goes to which field. The filled values are copies; readers can still change them.

### Text from a catalog \{#from-catalog}

A **Text** field can show a text of a catalog entry: turn on **From catalog**, pick the **Catalog**, name the value that holds the entry in **Entry named by** (a choice bound to the catalog, or a text with the entry's name in either language), and pick the **Text** — a clan's bane, a predator type's summary, or a text column of your own catalog. **Another text while a formula holds** switches to a second text, for example the variant bane while a toggle is on. **Shows** picks how:

- **A suggestion until the reader writes their own**: the text stands in the empty field; typing replaces it, and clearing the field brings it back;
- **The text only**: the field shows the text and readers cannot type into it; nothing is stored.

A name that matches no entry shows nothing.

### Your own catalogs \{#your-catalogs}

Make your own catalogs in the [library](./library.mdx): **New catalog** on a setting, or on a ruleset when every setting on those rules should share it. A catalog is a small table: every entry has a **Name** and a value in each of your columns — **Text**, **Number**, **Toggle**, or **Entry of a catalog**. Add entries one by one, or **Paste rows** copied from a spreadsheet: one entry per line, the name first, then the columns in order. Changing a column's type warns before values that do not fit are emptied.

The catalog picker lists **This setting**'s catalogs, then the catalogs of its rules, then the game's own. Pages of another setting or of other rules cannot bind yours. Use a catalog in three places:

- a **Choice** field: picking an entry fills the fields you map its columns to;
- a table column set to **Choice**: open **Settings** of the column; its columns fill the other columns of the same row only;
- a list with named entries: **Suggest from catalog** offers entries while the reader types a name, and **Value from** copies a column into the entry: a number column into a number, a rating, or a resource's current value; a text column into a text; a toggle column into a toggle. Typing a name that is not in the catalog still works.

An **Entry of a catalog** column says which entry of another catalog each entry belongs to — a rite to its relic, a power to its discipline: pick the column's catalog under its type, then an entry in each cell. A cell whose entry was deleted keeps its value and is marked.

**Limit by parent** on a catalog choice keeps rows to the parents on the page: name the **Parent list** (a list whose entries follow the parent catalog), the **Detail naming the parent** (the entry column), and, if entries have levels, the **Detail with the level**. The choice then offers only entries of the parents in the list, up to each parent's rating; with no parent in the list it offers everything. A row picked before the rating dropped stays and is marked "above" its parent. The game's own lists of rows (V5 powers) take the same limit in their settings.

Documents remember which entry they picked: renaming the entry renames it on every sheet. Deleting an entry or the whole catalog keeps the picked name on the sheets, and the fields go back to their own list of options. Moving a catalog to a place some pages cannot see is confirmed first and names those pages. The game's own catalogs are listed in the library read-only.
