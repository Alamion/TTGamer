# Отправка бросков

:::tip[Коротко]
Откройте настройки кубов, выберите **Сервис**, вставьте адрес вебхука и включите **Делиться бросками**. После этого каждый бросок появляется в канале или комнате вашей группы. Адрес Discord берётся из настроек канала; адрес Matrix выдаёт администратор вашего сервера, который один раз разрешает этот сайт.
:::

Модуль кубов отправляет каждый бросок — имя персонажа, нотацию и итог, прочтение и кубы — в один чат. Броски, сделанные почти одновременно, объединяются в одно сообщение. Кнопка рядом с настройками кубов показывает логотип выбранного сервиса: левый клик включает и выключает отправку, правый скрывает данные персонажа (имя и характеристики).

У каждого сервиса свой адрес, поэтому между Discord и Matrix можно переключаться, не вставляя адрес заново. Адреса хранятся, пока открыта вкладка браузера, и никуда не отправляются, кроме самого сервиса.

:::caution[Адрес вебхука — это пароль]
Любой, у кого есть адрес, может писать в ваш канал или комнату. Делитесь им только с группой и попросите новый, если он утёк.
:::

## Discord \{#discord}

1. В Discord откройте **Настройки канала → Интеграция → Вебхуки** (нужно право **Управлять вебхуками**).
2. Создайте вебхук, назовите его (например, «Кубы») и нажмите **Копировать URL вебхука**.
3. В настройках кубов выберите **Discord** и вставьте адрес. Он выглядит как `https://discord.com/api/webhooks/…`.

Сообщения в Discord никого не оповещают: упоминания в имени персонажа показываются как текст.

## Matrix \{#matrix}

Комнаты Matrix получают броски через generic webhooks [matrix-hookshot](https://matrix-org.github.io/matrix-hookshot/latest/setup/webhooks.html). Игрок не настроит это сам: администратор сервера один раз включает вебхуки, а кто-то с правами модератора создаёт вебхук для комнаты.

**Администратор** включает generic webhooks в конфигурации hookshot:

```yaml
generic:
    enabled: true
    urlPrefix: https://matrix.example.org/webhook/
    # Отвечать только после того, как сообщение попало в комнату, — так модуль кубов сообщит об ошибках.
    waitForComplete: true
```

**В комнате**:

1. Пригласите бота hookshot.
2. Отправьте `!hookshot webhook dice` (имя любое). Бот ответит адресом вебхука.
3. Передайте адрес игрокам. В настройках кубов они выбирают **Matrix** и вставляют его.

Используйте **незашифрованную комнату**: hookshot может не суметь писать в зашифрованную, а модуль кубов этого не заметит.

Форматирование то же, что в Discord: имена и итоги жирным, исходы цитатой, кубы блоком кода. `@room` в броске никогда не оповещает комнату. Клиент Matrix всё же может подсветить сообщение участнику, если в нём встречается его отображаемое имя, — например, у персонажа с именем как у игрока.

## Разрешение для сайта \{#site-permission}

Браузер отправляет бросок прямо на сервер. Само сообщение доходит, но ответ сервера браузер покажет модулю кубов, только если сервер разрешил этот сайт. Без разрешения каждый бросок заканчивается ошибкой «Не удалось связаться с комнатой Matrix», даже если он доставлен.

Администратор добавляет один заголовок, `Access-Control-Allow-Origin`, к ответам с пути вебхуков на обратном прокси перед hookshot. Разрешите `https://ttgamer.vercel.app` и `http://localhost:3000`, если кто-то разрабатывает сайт локально. Обрабатывать `OPTIONS` не нужно: модуль кубов отправляет обычную форму.

nginx:

```nginx
map $http_origin $ttgamer_origin {
    default "";
    "https://ttgamer.vercel.app" $http_origin;
    "http://localhost:3000" $http_origin;
}

location /webhook/ {
    add_header Access-Control-Allow-Origin $ttgamer_origin always;
    add_header Vary Origin always;
    proxy_pass http://127.0.0.1:9000/webhook/; # адрес вебхуков вашего hookshot
}
```

Caddy:

```text
handle /webhook/* {
    @ttgamer header_regexp Origin ^(https://ttgamer\.vercel\.app|http://localhost:3000)$
    header @ttgamer Access-Control-Allow-Origin {http.request.header.Origin}
    header Vary Origin
    reverse_proxy 127.0.0.1:9000 # адрес вебхуков вашего hookshot
}
```

## Проверка адреса \{#test-address}

Отправьте тестовое сообщение из терминала (подставьте свой адрес):

```bash
curl -i -X POST --data-urlencode 'text=**Тестовый бросок** = 7' https://matrix.example.org/webhook/abc123
```

Ответ — `200`, в комнате появляется «**Тестовый бросок** = 7». Затем проверьте разрешение для сайта:

```bash
curl -i -X POST -H 'Origin: https://ttgamer.vercel.app' --data-urlencode 'text=Проверка разрешения' https://matrix.example.org/webhook/abc123
```

В ответе должен быть `Access-Control-Allow-Origin: https://ttgamer.vercel.app`. Если обе проверки прошли, бросок из модуля кубов доходит до комнаты без сообщения об ошибке.
